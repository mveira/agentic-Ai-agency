# Website build playbook

Distilled reusable patterns for shipping a Pattern-B (Vercel-hosted Next.js)
client marketing site. Read top-to-bottom before starting a new engagement;
each section is a copy-paste-ready convention.

The reference implementation that produced this playbook is the
C Through Exteriors build — `~/Development/agentic-agency/site-c-through-exteriors/`
and `mveira/cthroughwindows` on GitHub.

## Stack defaults

| Layer | Choice | Rationale |
|-------|--------|-----------|
| Framework | Next.js 14, App Router | Per-route render mode, server actions, native middleware |
| Language | TypeScript strict | Already monorepo convention |
| Hosting | Vercel (Pattern B = standalone repo) | Free tier covers marketing sites; admin + form endpoints colocate cleanly |
| Fonts | `next/font/google` — two faces (heading + body) | Self-hosted, no CLS, no third-party blocking |
| Content | JSON in `content/*.json`, Zod-validated | No DB needed; git history = audit trail |
| Tests | Vitest | Already monorepo convention |
| Email forward | Resend HTTP API via `fetch` | No SMTP / nodemailer dep |
| Admin auth | HMAC-signed cookie + Web Crypto | No NextAuth dep; runs in Edge + Node |
| Icons | `lucide-react` | Already vetted; tree-shakeable |
| Motion | `motion` (Framer rebrand) | Already vetted; `MotionConfig reducedMotion="user"` global |

## Engagement bootstrap (first hour)

1. **Find the real client.** Don't accept "new-client-2026-MM-DD" as a
   long-lived slug — it'll bleed into commits, package names, and CI.
2. **Open the live site.** Curl the homepage + an interior page +
   robots + sitemap into `/tmp/<slug>-audit/`. Grep for `<title>`,
   `srcset`, `background-image: url(...)`, fonts.
3. **Open the logo.** `Read` the PNG/SVG directly. Whatever the
   audit's CSS scrape says, the **logo file is the source of truth**
   for brand palette + character.
4. **`file` every image** before treating any of them as hero. Many
   "logos" / "thumbnails" on legacy sites are 70×70 icons.
5. **List the legacy URLs.** Every `.html` you find on the live site
   becomes a 301 redirect entry in `next.config.mjs` so existing SEO
   equity isn't lost.

## Repo extraction (Pattern B)

The site starts life as a scaffold in `agency-agents/apps/site-<slug>/`,
then graduates to its own repo for Vercel deploy.

```bash
# From inside agency-agents
git subtree split --prefix=apps/site-<slug> -b client-extract

mkdir -p ~/Development/agentic-agency/site-<slug>
cd ~/Development/agentic-agency/site-<slug>
git init -b main
git pull ~/Development/agentic-agency/agency-agents client-extract \
  --allow-unrelated-histories --no-rebase

# Housekeeping in the new repo
# - inline tsconfig (drop `extends "../../tsconfig.json"`)
# - drop `output: 'export'` from next.config (Vercel-hosted)
# - rename package.json `name` to bare slug
# - rewrite README for Vercel deploy
# - add packageManager: pnpm@<version> + engines.node >=20

# Back in agency-agents
git rm -r apps/site-<slug>/
git branch -D client-extract
# (commit the removal; the dossier stays in SPYN)
```

After housekeeping commit, push the new repo to GitHub:

```bash
gh repo create <slug> --private --source=. --push
```

## SEO + LLM-SEO baseline

Required per `nextjs-site-craft/v1` + `llm-optimisation/v1`:

- **Per-page metadata** — every page exports `metadata` with `title`,
  `description`, `alternates.canonical`, `openGraph`, `twitter`.
- **JSON-LD schemas**:
  - LocalBusiness — every page (mount in root layout)
  - Service — every service page
  - BreadcrumbList — every inner page
  - FAQPage — every service page (paired with visible FAQ)
- **`public/llms.txt`** — site summary + page index for AI crawlers.
- **`app/sitemap.ts` + `app/robots.ts`** — generated, never static.
- **Legacy redirects in `next.config.mjs`** — every old `.html` URL
  301s to the new clean URL.
- **One H1 per page.** Section-level H2s with a small `::after` accent
  (3px coral underline) for brand consistency.

## Accessibility baseline

- Skip link first focusable element (`<SkipLink />` in root layout body).
- `<main id="main">` on every page.
- `<nav aria-label="...">` on every nav; `aria-current="page"` on the
  current breadcrumb item.
- Form inputs always have `<label>` + `aria-invalid` on validation
  failures.
- Lucide icons use `aria-hidden="true"`; meaningful icons use
  `aria-label`.
- `<details>`/`<summary>` for the FAQ — native keyboard a11y.
- Reduced motion: `<MotionConfig reducedMotion="user">` at the
  marketing root; only animations with a job survive (see
  `motion-design/v1` skill).

## Lead-forward email (Resend)

`app/api/lead/route.ts` accepts either `application/json` (legacy) or
`multipart/form-data` (current — needed for attachments), validates
the payload, logs it, and optionally fires an email via Resend with
inline attachments:

```ts
if (process.env.RESEND_API_KEY) {
  await fetch('https://api.resend.com/emails', {
    method: 'POST',
    headers: { Authorization: `Bearer ${process.env.RESEND_API_KEY}` },
    body: JSON.stringify({
      from, to, subject, text, html,
      attachments,  // [{ filename, content (base64), contentType }]
    }),
  });
}
```

Env vars: `RESEND_API_KEY`, `LEAD_EMAIL_TO`, `LEAD_EMAIL_FROM`.
Failure to send doesn't fail the form submission — log is the audit
trail.

### Attachments

The quote form supports plans + site photos as attachments — clients
often want to send these with their initial enquiry. Implementation:

- Form: hidden `<input type="file" multiple accept="image/*,application/pdf">`
  surfaced via a styled "Choose files" pill + chip-list of selected
  files with remove buttons. Client-side limits: 4 files max, 8 MB
  per file, 25 MB combined.
- Form submits `FormData` (multipart) when files are present.
- API route reads `req.formData()`, validates each file against the
  same limits (silent drop on type/size mismatch), base64-encodes,
  passes to Resend as the `attachments` array.
- Never persisted server-side. Attachments live in the email Kington
  receives; if they need long-term storage, they save the email.

Resend's per-request payload cap is 40 MB; our 25 MB combined limit
keeps comfortably inside it.

## Analytics + cookie consent

Standard add for every Pattern-B site. Two providers, one consent
flow.

- `<Analytics />` component reads `NEXT_PUBLIC_META_PIXEL_ID` and
  `NEXT_PUBLIC_GA_MEASUREMENT_ID`. If both unset, renders nothing.
  Loads via `next/script` with `strategy="afterInteractive"`. GA4
  init sets `anonymize_ip: true`.
- `<CookieBanner />` component pins a small accept/reject bar to the
  bottom on first visit. Choice persists to `localStorage` under
  `cookie-consent`; dispatches a `cookie-consent-changed` custom
  event when set.
- The Analytics component listens for that event + the native
  `storage` event so the scripts mount the moment the user accepts,
  no page reload.
- Per UK GDPR / PECR: nothing fires until consent is `accepted`.
  This is the default; the spec requires it.

Both components live in `app/(marketing)/_components/` and mount as
siblings under `<body>` in `app/layout.tsx`, outside the
`<MotionProvider>` tree (no React-state coupling).

## Admin CMS (lightweight)

Reference implementation: see `lib/admin-auth.ts` + `lib/content-write.ts`
+ `middleware.ts` + `app/admin/**` in the C Through Exteriors repo.

Pattern:

- **Auth**: `ADMIN_PASSWORD` env var + HMAC-SHA256 signed cookie via
  Web Crypto. Works in Edge runtime (middleware) and Node (server
  actions). 7-day session TTL. Constant-time string compare for both
  password and signature checks.
- **Middleware** guards `/admin/**` except `/admin/login`; redirects
  with `?next=` to preserve destination.
- **Server actions** use Next 14's `useFormState` + `useFormStatus`
  (React 18.3). **Not `useActionState`** (that's React 19).
- **Login page** wraps the form in `<Suspense>` because
  `useSearchParams()` forces CSR-bailout on prerender.
- **Persistence**: two modes, swap controlled by `GITHUB_TOKEN`
  presence (see `lib/github-content.ts`):
  - Local dev (no token): writes to `content/*.json` via `node:fs`.
  - Vercel production (token set): writes via the GitHub Contents
    API. Each save → commit on the configured branch → Vercel
    auto-redeploy → new content live in ~30–60s. Audit trail = the
    commit history.
  - Env vars: `GITHUB_TOKEN` (repo scope), `GITHUB_REPO_OWNER`,
    `GITHUB_REPO_NAME`, `GITHUB_DEFAULT_BRANCH`.
- **Recovery**: rotate `ADMIN_PASSWORD` in Vercel env vars. Optionally
  rotate `ADMIN_COOKIE_SECRET` too to invalidate all active sessions.

## Brand-gradient split CTAs

Two hero buttons sharing one continuous brand gradient:

```css
.hero__ctas .btn-primary,
.hero__ctas .btn-secondary {
  background-image: linear-gradient(90deg, <brand-start>, <brand-end>);
  background-size: 200% 100%;
  background-repeat: no-repeat;
  color: #fff;
  text-shadow: 0 1px 2px rgba(0, 0, 0, 0.35);
}
.hero__ctas .btn-primary  { background-position: 0% center; }   /* left half */
.hero__ctas .btn-secondary { background-position: 100% center; } /* right half */
```

Reads as one continuous gradient across two visually separate buttons.

## Pre-launch checklist anchor

Every engagement runbook MUST include:

- Lighthouse Performance ≥ 90 mobile (verify on Vercel preview)
- axe-core clean
- All legacy 301s curl-verified
- `RESEND_API_KEY` + `LEAD_EMAIL_TO` set in Vercel
- `ADMIN_PASSWORD` + `ADMIN_COOKIE_SECRET` set in Vercel
- `GITHUB_TOKEN` + `GITHUB_REPO_OWNER` + `GITHUB_REPO_NAME` +
  `GITHUB_DEFAULT_BRANCH` set in Vercel (so the admin CMS persists
  on the read-only serverless fs)
- GitHub repo connected to the Vercel project so admin commits
  trigger auto-redeploys
- `NEXT_PUBLIC_META_PIXEL_ID` and/or `NEXT_PUBLIC_GA_MEASUREMENT_ID`
  set if the client wants Meta / GA4 tracking
- Cookie banner verified: clicking Accept mounts analytics scripts
  within ~1s without a page reload
- Lead form attachment upload tested end-to-end: file picker accepts
  images + PDFs, validation surfaces size/count errors, Resend
  delivers the email with attachments inline
- Theme toggle removed (it's a design tool, not production)
- Reduced-motion check on the hero entrance animations
- Photo + logo + testimonials provenance confirmed in writing
- Real stat numbers verified, `VERIFIED = true` flipped
- Areas-covered list confirmed
- Rollback rehearsed once

## How to use this playbook in a new engagement

1. Open this file at the start of the engagement.
2. For each section, decide what's the SAME (most of it) and what's
   DIFFERENT (logo-derived palette, service list, copy, photos).
3. Copy the components and patterns wholesale where SAME.
4. Update the engagement's own runbook with the per-client values.
5. Append to the session log when you finish.
